기존 샘플 RG와 기존 Agent는 변경하지 않았습니다. 두 Agent는 별도 신원과 관측 리소스를 가지며 동일한 업무 환경의 읽기 권한만 준비했습니다. 기본 모드는 Review입니다.

새 자원은 유지되어 비용이 발생합니다. Agent 2개의 상시 비용과 모델 활성 사용량, AKS·ACR·로그 비용을 확인하세요. 자동 삭제는 하지 않습니다. 사용자 요청에 따라 로컬 소스 커밋을 준비하고 인증된 명령으로만 원격 게시합니다.

실행 검증

  • 리뷰 수정 후 단위·HTTP·계약 테스트 34개 통과. 이전 실제 CPU 기반 로컬 재현과 실제 ACR 이미지 빌드·AKS rollout 확인.
  • 결함 버전: A 약 3초, B 약 100ms, C 즉시 504. 같은 인스턴스의 후속 카드·계좌 요청도 실패.
  • 이전 AKS 복구 실측: A만 504, B 200·C 200. 카드·계좌 각각 새 요청 20건 실패 0건, p95 17ms·6ms.
  • Telemetry의 HTTP 메서드 속성을 보완해 실제 ResultCode 200·504 수집과 요청·종속성 상관관계 확인.
  • Azure Monitor 경고에서 Incident/Trigger 조사 스레드가 자동 생성되고 payment-specialist가 공유 Controller 결함과 stable/canary 영향 범위를 구분.
  • 서비스 맥락·런북의 업로드·색인·검색 확인. 팀 맥락은 synthesizedKnowledge의 overview.md에 저장되고 새 대화가 파일 출처를 읽어 정상 기준 설명.
  • 예약 작업은 Active 상태의 일회 실행에서 실제 결과를 반환했으며, 실행 이력 completed=true·success=true 확인 후 Paused로 복귀.
  • 네이티브 Payments Service Live Report를 갤러리에 저장. 버전 2, 저장 HTML, 강제 재조회한 실제 데이터와 도구 내부 상태 코드 검증.
  • Code Access 저장소 등록·연결 시험 isSuccessful=true. 저장소가 아직 비어 있어 실제 파일·배포 커밋 대조는 미완료.
  • 진행 가이드의 데스크톱·모바일 overflow, 아키텍처 이미지, 링크·복사 버튼 확인. 네이티브 포털 화면은 로그인 전이라 시각 검증과 분리.

발견한 제약

  • 현재 데모 노드 VM이 할당 해제된 상태를 발견했습니다. 전용 노드 두 개만 시작해 Ready는 확인했지만 Pod rollout은 제한 시간 안에 완료되지 않았습니다. taint를 임의 제거하거나 현재 전체 검증을 성공으로 표시하지 않습니다.
  • ARM 설정 변경은 비동기이며 바로 다음 변경을 보내면 OperationConflict가 발생할 수 있어 완료 대기를 추가했습니다.
  • 지식 업로드 직후 색인 실패·재색인 HTTP 500이 관측됐지만 이후 색인·검색·재색인은 성공했습니다. 초기 준비 시간과 실제 검색을 구분합니다.
  • Paused 예약 작업의 첫 수동 실행은 서버 측 200초 HTTP 타임아웃으로 종료됐습니다. Active 상태 실행은 완료되어 bounded resume/execute/wait/pause를 사용합니다.
  • 첫 온보딩 탐색은 복잡한 jsonpath 조회에서 Running 상태가 유지됐습니다. 해당 스레드를 오류 사례로 보존하고 새 팀 맥락 저장·조회 대화로 정상 결과를 확인했습니다. 원인과 중지 API는 확정하지 않았습니다.
  • 모델이 예약 점검에서 요청한 30분 대신 기본 1시간을 사용한 항목이 있어 담당 지침에 명시적인 시간 조건을 추가했습니다. 의미와 판단 품질은 원시 결과로 별도 평가합니다.
  • 기본 이미지 보안 진단에 High 경고 11개가 남아 있습니다. 최종 이미지는 ACR·AKS에서 실제 동작했지만 운영 사용 전 보안 검토가 필요합니다. 외부 API ingress는 없습니다.
  • 최신 AKS API는 현재 Bicep 타입 카탈로그에 없다는 경고가 있으나 ARM 미리보기·실제 배포·실행은 통과했습니다.

수정한 보호와 검증

  • RG 소유 태그·환경별 이름·ARM ID·실제 엔드포인트를 확인하고 다른 구독의 릴리스 파일을 거부합니다.
  • 승인 설명의 일부 문자열만으로 자동 승인하지 않습니다. 검토한 정확한 보고서 승인 ID만 처리합니다.
  • SIGINT·SIGTERM에도 Pause를 기다리고 강제 종료 후 복구 기록을 다음 실행에서 처리합니다.
  • 빌드 입력은 허용 목록으로 제한하고 중첩 환경 파일·개인 키·kubeconfig를 제외합니다.
  • 이전 Fired 해제 후 새 경고 ID를 현재 실행에 연결합니다. 오래된 복구 파일·다른 이미지·p95 초과는 실패합니다.
  • 초기·구성·현재 실행 검증을 분리하고 선택한 DEMO_TARGET을 사용합니다.
  • 저장된 보고서의 실제 호출·쿼리를 파서로 추출해 같은 인자로 검증합니다.
  • Operations Hub까지 같은 사건의 Agent를 유지하고 예약·보고서 단계에서만 전환합니다.
